# Wave 10 Research — implementation constraints

**Researched:** 2026-10-27. **Scope:** B → C → A for one developer, with Talos/hcloud staging. Primary documentation and repository code only. Findings are engineering evidence, not a compliance determination.

## Findings that correct the prior discussion

1. **Talos workload deployment is not systemd.** Talos v1.14 documents *extension services* as privileged containers packaged in system extensions, with boot-time service dependencies, OCI bind mounts, `restart: always` and `talosctl service ext-<name>` / `talosctl logs ext-<name>`. Extensions activate on install/upgrade, not by uploading a binary into `/opt`. Static pods need kubelet/Kubernetes, contradicting the no-Kubernetes goal. Prototype an extension service for Minga and NATS (or an externally managed NATS) and verify persistent paths, socket namespaces, networking and Talos upgrade behavior. Do not use `scripts/minga.service` as a Talos service. [Talos extension services](https://docs.siderolabs.com/talos/v1.14/build-and-extend-talos/custom-images-and-development/extension-services); [system extensions](https://docs.siderolabs.com/talos/v1.14/build-and-extend-talos/custom-images-and-development/system-extensions); [static pods](https://docs.siderolabs.com/talos/v1.14/configure-your-talos-cluster/images-container-runtime/static-pods).
2. **hcloud Public ISO exists; it is not a server image ID.** Talos's Hetzner page explicitly names the Public ISO schematic, but its `hcloud server create --image ${IMAGE_ID}` example uses a **snapshot** built via rescue/Packer/upload. The repository guide conflates these paths (`hcloud image list --type iso`). Correct it and verify against current CLI in a staging project before presenting runnable commands; do not repeat cost estimates without a current quote. [Talos Hetzner](https://docs.siderolabs.com/talos/v1.14/platform-specific-installations/cloud-platforms/hetzner).
3. **Talos encryption is not automatic.** Talos says disk encryption for `STATE`, `EPHEMERAL` and user volumes is **disabled by default**. The security checklist instructs operators to encrypt machine-config secrets. Plan encrypted volumes, off-repo config generation, scoped access and recovery; no plaintext credential samples. `nodeID` protection is weak against an adversary with the original host; TPM/KMS choices depend on environment. [Talos disk encryption](https://docs.siderolabs.com/talos/v1.14/configure-your-talos-cluster/storage-and-disk-management/disk-encryption); [security checklist](https://docs.siderolabs.com/talos/v1.14/security/talos-security-checklist).
4. **Talos PKI is for Talos, not automatically NATS.** The `MachineConfig` CA/node identity description does not promise issuing a workload certificate for Minga, nor mounting it at `/etc/minga/tls/`. Treat separate PKI issuance/provisioning as a prerequisite. Never export Talos CA/node private keys to NATS. [Talos MachineConfig reference](https://docs.siderolabs.com/talos/v1.14/reference/configuration/v1alpha1/config). Local containerd uses a Unix socket in `crates/minga-node/src/containerd/client.rs:55-76`; establish filesystem access control. Do not claim Talos supports TLS over this socket. Remote containerd TLS is a separate deferred conditional investigation.
5. **NATS encryption and identity are distinct.** NATS `tls { cert_file, key_file, ca_file, verify: true }` checks client certificates; `verify_and_map` also maps certificate identities into permissions. Monitoring listener is not protected by `verify`; keep on loopback. Cluster-route TLS requires its own cluster configuration. Existing `sidecar.rs:169-198` listens on all interfaces without TLS and starts only one server; `NatsBus::connect` is plaintext and called by manager, worker, `logs` and `agent ls`. Plan one connection configuration propagated to **every** caller, secure sidecar/external NATS modes, negative tests, rotation/reconnect, and identity/authorization. [NATS TLS mutual authentication](https://docs.nats.io/running-a-nats-service/configuration/securing_nats/auth_intro/tls_mutual_auth); [NATS TLS config](https://docs.nats.io/reference/config/tls/); [NATS cluster TLS](https://docs.nats.io/reference/config/cluster/tls).
6. **Secrets are metadata-only today.** `TaskSpec` has no secret refs (`crates/minga-state/src/types.rs:129-141`); scheduler `translate_secrets` creates only metadata (`crates/minga-scheduler/src/translate.rs:334-343`); OCI mount model already exists (`oci.rs:62-69,287+`). Compose parser supports top-level `secrets` and service refs. Add per-service references to task spec and API translation while keeping values off Raft. Provision local per-task files on verified Talos encrypted storage and bind read-only inside the OCI spec. Distinguish immutable versioned references from mutable rotations; reject missing refs before container creation. No `Secret` value in public API responses. Docker Swarm file secrets path is `/run/secrets/<secret_name>`; target/uid/gid/mode support must be scoped and tested. [Docker secrets](https://docs.docker.com/engine/swarm/secrets); [Compose specification](https://compose-spec.github.io/compose-spec/spec.html#secrets).
7. **Containerd does not provide an indexed log reader in the Tasks API.** `Tasks.Create` takes `stdout` and `stderr` destinations; current Minga runtime passes `"", ""` (`runtime.rs:152-157`), and `Runtime::logs` returns an empty vector (`runtime.rs:347`). Prototype two FIFO paths and reader startup **before** Create, test no deadlock with real Linux containerd + runc, and bound read buffers. Persist Minga-owned framed/log-line records plus optional offset index; do not call this a containerd standard binary index. Reuse `LogEntry`/JetStream `MINGA_LOGS`; report backpressure, reboot recovery, maximum bytes, failure TTL and successful-cleanup. [containerd Tasks API](https://github.com/containerd/containerd/blob/v1.7.0/api/services/tasks/v1/tasks.proto); [containerd runtime v2 IO](https://github.com/containerd/containerd/blob/v1.7.0/cio/io_unix.go).
8. **Compliance is not inherited.** FIPS 140-3 validates a specific cryptographic module and its operational environment, not a Rust crate dependency or generic TLS usage. SOC 2 is an independent examination of service-organization controls. VS-NfD / NATO accreditation depend on the classification, jurisdiction and contract authority; do not assert their criteria from a vague name. Create a control-and-evidence matrix, identify applicable scheme and assessor/authority, separately track supply-chain assurance, audit retention, access/revocation, crypto inventory and incident process. [NIST CMVP](https://csrc.nist.gov/projects/cryptographic-module-validation-program/fips-140-3-standards); [AICPA SOC 2](https://www.aicpa-cima.com/topic/audit-assurance/audit-and-assurance-greater-than-soc-2); [BSI approved products](https://www.bsi.bund.de/EN/Themen/Oeffentliche-Verwaltung/Zulassung/Hinweise-zur-Liste-der-zugelassenen-IT-Sicherheitsprodukte-und-systeme/hinweise-zur-liste-der-zugelassenen-it-sicherheitsprodukte-und-systeme_node.html).

## Recommended sequencing and gates

- **00 — Host feasibility:** Correct the design assumption first: Talos extension service in an ephemeral test VM, then hcloud staging; prove restart, persistent user-volume mount, containerd socket and networking. If unavailable, keep Talos deployment as blocked and do not claim staging success; use Linux VM for runtime tests only.
- **01 — B TLS:** Certificate issuance/provisioning decision, NATS client/route mTLS, identity ACLs, sidecar vs external startup, all CLI call sites; local containerd UDS permission boundary; test plaintext, wrong CA, expired cert, peer mismatch, rotation and offline restart.
- **02 — C secrets:** Per-service references through parser → scheduler → `TaskSpec` → supervisor → OCI; verified file provisioning & encryption; no Raft/bus value; negative/symlink/missing-secret/rotation tests.
- **03 — A logs:** Linux FIFO probe; split stream reader, Minga-owned bounded history and bus publishing, cleanup/reboot tests; explicit fallback decision to split regular files if FIFO cannot be demonstrated.
- **04 — staging & docs:** Full B/C/A demonstration on hcloud (or stop at explicit blocker), no secret leakage; update `README.md`, `docs/talos-deployment.md`, `scripts/setup-talos-minga.sh`, `scripts/minga.service` status, and security/compliance gap matrix. Do not claim previous README topologies are deployed.

## Validation Architecture

| Requirement | Automated proof | Integration/staging proof |
|---|---|---|
| W10-TLS | NATS config parsing, typed TLS options, rejected plaintext/wrong CA, identity ACL, cert rollover tests | NATS test instance/cluster; Talos extension-service startup; Unix socket permissions |
| W10-SEC | secret reference serialization; translation; mount allowlist; no-value-in-state snapshots; missing/escape/rotation cases | Linux container reads exact file at `/run/secrets/<name>`; no value in API/diagnostics |
| W10-LOG | FIFO lifecycle, framing and bounds, last-N/index, cleanup, restart recovery | Linux container stdout/stderr reaches `minga logs --tail` and `--follow` across restart |
| W10-STAGE | configuration validation; documented syntax audit | hcloud server boot, extension service starts, containerd socket, NATS TLS and workload executed; record non-secret evidence |
| W10-COMP | checklist/matrix source links and explicit unverified gaps | human authority review; no claim of audit/accreditation |

Quality gate at end of each implemented sequence, **unpiped**: `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, `cargo test`; record exit status separately. Skipped integration tests do not count as positive evidence. Never put keys, tokens, passwords, secrets, credentials or connection strings in evidence logs or summaries; redact any discovered values as `[REDACTED]`.
