# 10-04 — A: real stdout/stderr and bounded history

<objective>Capture real Linux-containerd output through separate stdout/stderr FIFO destinations, publish to JetStream and serve tail/follow while preserving stream identity, bounding disk and handling failures/restarts. A file-based fallback requires an evidence-backed decision, not silent substitution.</objective>

<must_haves>
<truths>
- D-04 and W10-LOG: A running Linux container emitting stdout and stderr produces separate entries in `minga logs TASK --tail 2` and `minga logs TASK --follow`; IDs/sequence and a durable cursor prevent loss or duplication across tested reconnect/restart windows, with explicitly bounded dedup/reconciliation guarantees.
- W10-LOG: FIFO readers are established before Tasks.Create; on failure, all shims, FIFOs, handles and partially created container/task state are cleaned without deadlocking.
- W10-LOG: Logs are retained for failed exits within finite TTL/quota and cleaned on **acknowledged and durably recorded** delivery; crash recovery and disk-full behavior are defined and tested.
- W10-SEC: Control-plane secret values/keys are never intentionally copied to the bus or diagnostics. Arbitrary workload stdout can contain secrets and is *not* covered by that absolute guarantee: treat it as sensitive, enforce subject/task authorization for logs and test cross-identity denial.
</truths>
<artifacts>Linux FIFO integration probe, Minga-owned log framing/index, lifecycle/retention tests and CLI/NATS end-to-end evidence.</artifacts>
</must_haves>
