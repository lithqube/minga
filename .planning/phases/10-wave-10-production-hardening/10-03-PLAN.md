# 10-03 — C: secure file-backed secrets end to end

<objective>Translate Compose secret references through scheduling into a safe per-task OCI bind mount at `/run/secrets/<name>`; keep values outside Raft and the event bus and provision node-local values on encrypted storage.</objective>

<must_haves>
<truths>
- D-03 and W10-SEC: Service referencing a secret fails before container creation if the named/versioned value is absent, unreadable or unsafe; Raft snapshots contain **references only**.
- W10-SEC: A workload reads the exact declared value at `/run/secrets/<name>`, read-only, without the value appearing in task env, API payloads, NATS events or error logs.
- W10-SEC: User-controlled secret names/targets cannot escape a fixed root, overwrite `/proc`/`/dev`, traverse directories or follow symlinks; duplicate destinations fail.
- W10-STAGE: Talos-backed provisioned files survive reboot and are encrypted at rest only when verified volume encryption and key custody are configured; no unverified machine-config encryption assertion.
</truths>
<artifacts>Task secret-reference model; scheduler/API translation; verified node-local resolver and OCI bind mount; secret provisioning/rotation runbook.</artifacts>
</must_haves>
