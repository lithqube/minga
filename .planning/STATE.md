Secrets are now staged per-task content-addressed: the runtime copies each resolved secret to `staged/<task_id>/<sha256>` (immutable, 0400) and mounts that inode — the exit property holds: a rotated secret is visible to a new task and not to a running one (`staging_tests::rotated_secret_is_visible_to_a_new_task_not_an_old_one`). Also fixed a pre-existing env-mutating-test race in `tls.rs` with an ENV_LOCK.

**Last Activity:** 2026-11-01

**Gate 1 outcome, verified live on a 2-node local cluster (macOS, MockRuntime):** `minga manager` self-registers on startup (id, bind address, libc-detected capacity, `--label` labels) and renews its lease every 10s (`NodeMembership` in `minga-node::registration`); placement excludes nodes with expired leases (`last_seen_unix` on `ClusterNode`, TTL 30s) and `POST /services/create` + `/update` fail with HTTP 409 when a service matches zero eligible nodes (`check_placeable` in `minga-scheduler`). `POST /nodes` registers out-of-band nodes; `POST /nodes/{id}/update` handles labels + `active`/`drain` and loudly rejects role changes, renames and `pause`. SIGINT marks the node `Left`; the API shows it `down` and new services get 409. Observed end-to-end: service create → 201 → 2 tasks placed → supervisor started both containers.

**Three pre-existing bugs found by the live run and fixed:** (1) `StateStore::propose` never forwarded writes — any upsert on a follower failed with `ForwardToLeader`; now forwards over the Raft RPC transport with bounded retry (regression test in `multi_node.rs`), which is also what the Docker API write path needs on non-leader nodes. (2) `minga api` ran no scheduler, so a cluster led by an API-only node placed zero tasks; it now runs the leadership-gated reconcile loop. (3) the generated sidecar NATS config had `max_memory_store`/`max_file_store` at top level, which nats-server 2.15 rejects; moved into the `jetstream {}` block. Also: Raft frames are now size-capped (64 MiB) — the unbounded length-prefix allocation from the roadmap's security list. JetStream stream/KV setup retries while the server finishes initializing.

**Known limitation (documented, not fixed):** a node cannot join an already-initialized cluster — `StateStore::open` initializes when pristine, so all members must start together (as `phase0` does). Raft membership changes (learner join, voter removal) are not part of Gate 1. A 2-voter cluster that loses one voter loses quorum; writes then time out — same semantics as a 2-manager Swarm.

**What Phase 11 adds.** A source audit plus a new executable probe (`crates/minga-cli/tests/deploy_path_probe.rs`, 3 tests) established four blockers that prevent a real deployment, none of which the earlier waves exposed because the tests supplied their own scaffolding:

- **B1 — no node registration. FIXED in Gate 1 (see above).** Nodes self-register with a lease; zero-eligible-node deploys fail with HTTP 409.
- **B2 — `minga deploy` does not deploy. FIXED in Gate 2.** `minga deploy` is now a client of the Docker Engine API (the shared write path): networks/secrets/configs are created idempotently, services created or updated, then task placement is awaited (`--wait`) and reported per service; unplaceable services fail the deploy with the API's 409 message. Stacks with volumes fail loudly (no volume API surface yet). One naming fix landed with it: the API's outbound `ServiceSpec.Name` is now the unique state ID (`stack.service`), not the colliding bare Compose name.
- **B3 — no container network. FIXED in Gate 3 (single-node scope).** Placement assigns deterministic IPs per task+network into `TaskSpec.ips` (travels over Raft and the bus); `minga-node::netns` (Linux) creates one bridge per network (gateway = first usable IP), a veth pair and named netns per task, iptables DNAT for published ports, and a per-task resolv.conf bind-mounted into the container; the OCI network namespace now points at it. A DNS server per bridge gateway answers `<svc>`, `tasks.<svc>`, `<svc>.<stack>.minga.local` and task FQDNs from cluster state, never NXDOMAINs overlay names (for any qtype — musl companion-AAAA safe), and proxies everything else upstream. WireGuard mesh / multi-node networking remains open.
- **B4 — Compose fidelity. FIXED in Gate 4.** `command`, `entrypoint`, `labels`, `healthcheck`, volumes (named + bind) and placement constraints flow Compose → state → API → OCI: entrypoint/command override image Entrypoint/Cmd with Docker semantics (`ImageConfiguration` split), named volumes materialize under `<data_dir>/volumes`, mounts are bind-mounted (ro honored), labels and `Placement.Constraints` are visible in the API, tasks carry `NetworksAttachments` with real `ip/prefix` (Traefik requires the prefix), and the supervisor writes lifecycle transitions (`running`/`stopped`) to the task record so Docker consumers see live state. Two real bugs found by Traefik: `parse_filters` only accepted the array form — Docker's Go client sends `{"service":{"x":true}}`, which silently yielded *no filtering at all*; and startup leader-election timeout killed nodes that missed a 10s window (now waits with loud logs — a restarted 2-voter cluster recovers). Unsupported mount kinds (tmpfs etc.) fail loudly.

**Transport security state (post-Gate 5):** NATS TLS is production-shaped (no insecure escape hatch, CA + client cert required, mandatory SAN verification), plus optional token auth. Raft is mTLS when the three `--raft-tls-*` flags are set (server requires client certs; frames capped at 64 MiB) — plaintext remains the default for development. The Docker API supports a required bearer token via `--api-token`; **it still binds `0.0.0.0:2375` by default and without a token it is unauthenticated RCE by design** — the flag's help says so. PKI lifecycle is operator-run via `minga tls` (issue/rotate by re-issuance + rolling restart); an embedded self-issuing CA is not in v0.1.0.
