# antislop audit 002: mobile layout (2026-11-02)

Scope: the site on `main` at `8f8a6dd`, built and served locally. Skill: antislop-layoutmobile. Mode: after. Nothing has been changed; pick the numbers to fix.

Priority follows the governing rule's tier. R-03 (mobile) and R-39 are Hard Gate, so HIGH; R-05 is a Quality Lock, so LOW.

## How it was measured

Playwright, 11 page types × 7 widths (320, 375, 600, 768, 900, 1024, 1280), dark theme. For each: horizontal overflow, nav mode, docs grid columns, h1 size and line count, section padding, rendered height of every SVG diagram label, and every standalone tap target (links outside running prose, buttons, summaries; links inside closed menus excluded). Screenshots at 375px for the diagrams.

## Findings

### HIGH

1. **Diagrams are unreadable on phones (R-03).** Mermaid diagrams scale down to the column width, so their labels shrink with them. At 375px, 71 of 147 labels on `/architecture/` and all 36 on `/docs/quickstart/` render under 10px tall; the deployment-topologies diagram is a thin strip. The problem persists on desktop: at 1280px, 24 of 36 quickstart labels are still under 10px, because the diagram is wide and the docs column is 72ch. The landing page's process diagram has 15 of 26 labels under 10px at 375px (about 5px). The hero diagram is fine because it switches to a vertical layout under 640px. Fix: give every diagram a minimum rendered width inside a labelled horizontal scroll region (as the comparison table already does) so labels stay at least 12px, and give the process diagram a vertical phone layout like the hero's.
2. **Standalone tap targets under 44px (R-03, R-39).**
   - Footer link lists are 32px tall with 0px between them (12 per page).
   - Breadcrumb links are 15px.
   - Docs sidebar links are 34px, desktop nav links 37px, the version pill 19px, "Skip to content" 42px.
   - On the landing page, the crate links in the architecture section are 18px, and the compact feature titles and lead-card links are 18 to 23px.
   Inline links inside sentences are excluded (they are allowed to stay text-sized). Fix: padding to 44px on link lists (footer, sidebar, breadcrumb, nav, version pill, architecture lists, feature titles), keeping the visual size and spacing the list items so a thumb can't hit two.
3. **Docs page titles use one fixed size at every width (R-03, R-06).** The docs h1 is 33px from 320px to 1280px. The ADR 0003 title wraps to 6 lines at 375px and 8 at 320px, filling the first screen before any content. Fix: a fluid size for the docs h1 (for example `clamp(1.6rem, 5vw, 2.074rem)`) and one smaller step for h2/h3 under 640px.

### LOW

4. **Mobile section padding is two-thirds of desktop (R-05).** Landing sections use 64px top and bottom on phones against 96px on desktop, so a 375px screen often shows a third of a screen of empty space between sections. Fix: about 40px on phones.
5. **The "Menu" label sits at the top of its button (R-03).** In the mobile header, "Menu" is top-aligned while "Dark theme" beside it is centered, so the two controls look misaligned. Fix: center the summary text (the global summary padding and the flex rule are fighting).

## Passed (with evidence)

- No horizontal scroll on any of the 11 pages at any of the 7 widths.
- The navigation collapses into a labelled "Menu" disclosure below 1040px, and the desktop link row only appears when it fits.
- Layout states are defined across the range, not just phone and desktop. The docs grid is 1, 2 and 3 columns (below 960, 960 to 1199, 1200 and up). The landing feature list is 1, 2 and 3 columns (below 640, 640 to 959, 960 and up). The hero, problem and fit sections stack below 960.
- The hero diagram switches to a vertical layout below 640px.
- No `100vh` sections; sections size to their content.
- No hover-only interactions: every hover state has an `:active` state, and menus are `<details>` that open on tap.
- The sticky header is 56px, and `scroll-padding-top` keeps anchored headings out from under it.
- Copy buttons, the theme toggle, the Menu summary and the primary buttons are at least 44px.
- Wide tables and code blocks scroll inside their own labelled regions instead of widening the page.
